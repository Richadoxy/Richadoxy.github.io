# 触觉记忆的实验设计：从研究假设到数据与闭环证据

> 全掌触觉、历史窗口、GRU 和对象级 slots 都可能帮助操作，但“模型更复杂”本身不能说明提升来自哪里。本文把触觉记忆研究拆成可检验的假设，说明怎样采数据、设对照、隔离特权标签，并评价真实控制收益。
>
> 表示与架构基础见[触觉输入怎样构建](39_tactile_input_representation.md)和[策略记忆与对象级触觉状态](40_policy_memory_and_object_centric_tactile_state.md)。下文的任务、流程与表格是实验设计建议，不是已完成的实验或已有成绩。

## 0. 一条完整的证据链

触觉记忆研究可以沿着下面的顺序展开：

```text
当前观测缺少什么信息？
            ↓
过去的哪段触觉 / 视觉可以补充？
            ↓
模型以什么状态保存、如何更新？
            ↓
这些状态是否改变了动作？
            ↓
动作改变是否改善任务结果？
```

例如，遮挡下操作两个物体时，当前压力图可能无法直接说明“这片接触属于 A 还是 B”。可见时的身份、先后接触顺序和随后的动作，可以为归属提供线索。对象级记忆尝试保留这些线索，策略再利用它们调整 B、保留 A。

这个故事包含几个不同主张，不能用一个总成功率同时证明。接触归属预测更好，说明状态表示更有信息；保护物体更少掉落，才进一步支持控制价值。

## 1. 把大故事拆成几个可检验的假设

| 假设 | 需要比较什么 | 哪种结果不足以支持它 |
| --- | --- | --- |
| 掌面覆盖提供额外信息 | 相同策略，保留/移除真实掌面输入 | 只比较有触觉与纯视觉 |
| 历史有助于决策 | 当前观测、长窗口、递归记忆 | 记忆模型同时用了更多模态或更快反馈 |
| 对象级状态有额外价值 | 相同历史与身份信息的全局记忆、对象 slots | 只打败无记忆模型 |
| 新触觉用于遮挡后纠正 | 遮挡后才施加扰动，并观察后续动作 | 一直执行可预先记住的固定轨迹 |
| 方法具有一定泛化 | 预先定义的未见对象/组合/时长/会话 | 同一轨迹随机分帧后的高分 |

如果长窗口模型已经能稳定完成任务，这仍然是有价值的结果：说明所需历史可能有限，不一定需要复杂记忆。如果对象 slots 没有优于匹配的全局模型，应收缩表示层面的结论，而不是只挑它能打败的弱基线。

## 2. 先验证机械任务，再验证学习算法

任务需要让硬件有机会完成，也需要让待研究的信息真正重要。

以“保持 A，同时移动 B”为例，首先要确认 A 有可承托的区域、工作手指能够接近 B，而且移动 B 时存在不破坏 A 支撑的动作。若手型和物体组合本身不允许这种操作，增加模型或示范数量无法修复机械不可行性。

一个递进的任务设计可以是：

1. 单物体接触建立、保持和释放，确认传感器与控制链路。
2. 可见时建立对象状态，随后遮挡，完成单物体保持或小范围调整。
3. 已初始化的两个物体中，移动一个、保留另一个。
4. 在前面条件上增加选择性释放、角色交换与遮挡后扰动。

固定腕部、预放置物体的原语可以降低初期难度，但它证明的是限定起始条件下的操作。若后续要宣称桌面获取、存放再抓取，就要另外评测完整过程。

初始化夹具也要与评分阶段分开。若任务要求自主保持，成功判断阶段不能仍由桌面或夹具承担物体重量。

## 3. 让“需要记忆”成为任务性质

### 3.1 包含完整的信息链

训练和测试都应包含：

```text
可见时建立身份 / 位置线索
              ↓
发生接触，记录与动作相关的变化
              ↓
遮挡持续一段时间
              ↓
需要依赖过去信息的调整或选择
```

只在最后一帧盖住相机，模型可能仍依赖紧邻的视觉；若关键事件总发生在固定时刻，模型也可能只记住时间进度。遮挡起点、持续时间与任务变化需要有合理变化。

为了判断历史是否有信息，可以先训练一个小的状态预测诊断：比较当前观测和一段历史对位置、接触区域或事件标签的预测能力。这是数据与可观测性的检查，不能替代闭环控制实验。

### 3.2 在遮挡之后再扰动

假设模型在遮挡前看清了物体位置。若遮挡后环境始终不变，它可能仅靠初始视觉和一段固定动作就完成任务。

更有区分力的协议是：先建立相同的初始视觉条件，遮挡之后再施加可控的轻微位移、接触变化或姿态扰动。随后检查新触觉是否让纠正动作发生了相应变化。

扰动方向、时刻和强度不应以隐藏标签的形式输入策略。可以把它们记录为评测元数据，用来分析不同条件下的表现。

### 3.3 对象身份、获取顺序和任务角色分别变化

多物体任务中，不能总是“先抓到的 A 要保留，后抓到的 B 要释放”。否则模型可能学会固定顺序规则，不必维持对象状态。

应在机械可行的范围内平衡物理对象、获取顺序、目标角色和目的区域。例如同一对象组合分别执行“移动 A、保留 B”和“移动 B、保留 A”。所有比较方法都得到同等的任务条件。

角色交换不是要求硬件完成不可能的动作；不可达配置应在任务定义阶段排除，并清楚报告可行范围。

## 4. 区分感知数据、动作示范和评价标签

| 数据类型 | 记录内容 | 能直接训练什么 |
| --- | --- | --- |
| 接触探索数据 | 单点/多点接触、滑动、压力和图像 | 重建、接触识别、部分位置或区域表征 |
| 有效动作示范 | 同步观测与真实执行命令 | 行为克隆与动作生成 |
| 恢复示范 | 扰动或偏离后的纠正动作 | 对相应状态的恢复行为 |
| 独立状态标签 | 物体位置、接触归属、可见性 | 辅助监督与感知评估 |
| 成功/失败与质量标签 | 保持、掉落、误释放、接触质量 | 结果评估、评价模型或有定义的筛选 |

例如，一个数据集即使有很多真实触觉帧，如果 action 列只是占位零向量，就不能直接作为动作专家数据。触觉表征预训练与模仿学习需要不同的数据前提。

真实关节位置也不能自动替代命令。位置控制中的目标关节位置、实际测量位置和增量动作是不同变量；力控、阻抗或速度控制又有各自接口。先定义策略到底输出什么，再确定示范标签。

### 4.1 示范应包含反馈—动作对应关系

若示范中从未出现“接触变弱后重新建立支撑”，模型很难仅凭额外触觉学会正确恢复。需要的数据不仅是传感器与动作同时存在，还包括可学习的反应行为。

[RDP 原文](https://arxiv.org/abs/2503.02881)同时研究执行中的高频触觉反馈与带反馈的示范采集，说明策略接口和数据采集需要一起设计。更一般地，[robomimic 的系统研究](https://arxiv.org/abs/2108.03298)考察了离线人类示范质量、算法选择和评估之间的关系，提醒我们不能仅凭训练损失判断部署能力。

失败轨迹也有价值，但用途要明确。成功的恢复段可以作为相应动作监督；持续错误的动作不能无区别地标成正确示范。失败事件还可以用于评价、失败预测或后续数据采集。

### 4.2 一条轨迹至少应保留的上下文

一个概念性数据结构如下，不要求绑定特定存储库：

```text
episode
  ├─ sensor_version / mapping_version / hand_side
  ├─ 原始压力、有效性、饱和信息
  ├─ 实际存在的指尖力或视触觉图像
  ├─ 允许给策略的视觉与可见性
  ├─ 关节 / 腕部状态、各流时间戳与接收时间
  ├─ 实际下发命令、控制模式、单位、限位与时间
  ├─ episode 内对象身份、目标 / 保护角色
  ├─ 辅助标签及逐项有效性
  └─ 结果、恢复片段、示范质量与数据来源
```

不同硬件版本应使用各自真实存在的模态。掌面压阻＋三维力，与多区域压阻＋指尖图像，可以共用一部分训练思想，但不能靠字段名称相似就视作相同传感器。

## 5. 标签可以更完整，策略输入必须可部署

遮挡实验仍需要知道物体实际发生了什么。独立相机、跟踪器或仿真真值可以提供标签，但要与策略输入隔离：

```text
策略可见的相机、触觉、本体状态、历史动作 → 模型 → 动作
                                                      │
独立评测相机 / 跟踪器 / 仿真真值 ───────→ 标签与评估 ←───┘
```

训练时，位置真值可以作为位置辅助头的目标；对象—区域接触可以作为 ownership 目标。它们不因此获得进入主策略条件的资格。

常见的隐蔽泄漏包括：

- 用隐藏物体真值生成紧贴物体的遮挡 mask，mask 边缘反而暴露位置。
- 物体掉落后根据真值关闭其 slot，让模型直接知道失败事件。
- 遮挡期间继续从独立相机提供 crop、box 或精确位置。
- 用未来样本插值当前观测，或用未来专家动作冒充上一执行指令。

遮挡可以使用物理挡板，或根据允许的机器人运动学信息构造保守的手部遮挡包络。具体方式需保证所有方法看到同样的信息。

### 5.1 特权 teacher 的正确位置

仿真 teacher 可以读取物体位姿等特权状态来生成专家轨迹。部署 student 则只能读取实际可用的观测。两者接口应明确分开。

即使没有直接泄漏，teacher 的动作也可能依赖 student 无法区分的隐藏状态。如果两个可观测历史几乎相同，却要求 student 复现完全不同的确定动作，这仍是可观测性问题。需要重新设计任务、增加可用线索，或接受不确定性，而不是假设蒸馏一定消除信息缺口。

仿真 link 接触力也不天然等于真实 taxel 阵列或视触觉图像。没有经过验证的传感器模型时，可以先利用粗接触标签或可对应的动作信息，另用真实数据学习传感器编码；不能把复制出来的力值当作逼真密集触觉。

## 6. 用匹配的 baseline 定位收益

建议按由简到繁的顺序建立对照：

| 方法 | 输入与历史 | 主要回答的问题 |
| --- | --- | --- |
| 当前观测 Visuotactile DP | 当前视觉、触觉、本体状态 | 基础链路是否可学 |
| 长窗口 DP | 相同模态，显式增加历史窗口 | 直接读取过去是否已经足够 |
| Global Temporal DP | 相同允许历史，单个全局记忆 | 一般递归记忆的收益 |
| 区域记忆 DP | 区域触觉与相应时序状态 | 保存空间分工是否有用 |
| 对象级记忆 DP | 相同身份初始化、历史与任务条件 | 对象分解是否进一步有用 |
| 特权状态 oracle | 额外读取真实隐藏状态 | 可观测信息与控制上限之间的差距 |

Oracle 应单列，不能和可部署策略混成公平主比较。反过来，也不能只给对象级方法初始身份、目标和保护角色，却要求全局模型自行猜测这些信息。

### 6.1 控制输入之外，还要匹配执行条件

至少记录并尽量匹配：

- 示范、数据划分与训练预算；
- 辅助标签、辅助损失和它们的训练权重；
- 可用视觉、触觉、关节和历史动作；
- 历史覆盖的物理时长；
- 动作表示、低层控制器与限位；
- 重规划频率、执行前缀、推理延迟与去噪预算。

模型大小和计算量未必能逐项完全相同，但应报告差异，必要时增加参数或延迟匹配的对照。若新方法每步更新，而 baseline 连续开环执行很长动作块，结果同时包含了反馈时序优势，不能全部归因于记忆表示。

### 6.2 掌面、时间和对象结构分别消融

硬件层面比较“全输入”和“移除掌面输入”；时间层面比较当前、窗口、递归状态；对象结构层面比较 global 与 slots。这样才能分清哪一层贡献了收益。

辅助监督也要单独拆开：如果对象 slots 额外使用接触归属标签，而全局模型只使用动作损失，性能差异就同时包含了结构与监督的影响。可给全局模型增加读取相同标签的辅助预测头，并增加“保留 slots、移除接触归属监督”的消融，区分对象结构本身和额外标签的贡献。

移除传感器的主要消融宜独立训练对应模型，并使用明确的缺失标志。仅在测试时把输入突然置零，会引入分布变化，更适合作为鲁棒性诊断。

类似地，遮挡后清空动态记忆可以检查历史依赖，但也改变了隐藏状态分布。若要检验动态记忆，应保留相同的初始身份信息，并结合正常训练的无记忆或短历史对照，避免把一次破坏性干预当成完整因果证明。

## 7. 指标要覆盖“完成目标”和“保住其他对象”

多物体选择性操作不宜只评价目标对象是否到位。可以把主要成功定义为：

\[
S_{\rm joint}
=\mathbf 1\{
\text{目标操作完成}\land
\text{保护对象满足保持要求}\land
\text{无误释放}\land
\text{满足预定稳定条件}
\}.
\]

其中保持要求、稳定时长、接收区域和允许误差应在独立 pilot 后固定，不能看到测试结果再反复调整。

| 层次 | 可报告指标 | 对应结论 |
| --- | --- | --- |
| 任务 | 联合成功率、正确释放率、超时率 | 整体行为是否有效 |
| 保护对象 | 掉落率、误释放率、位移 | 是否完成选择性控制 |
| 状态估计 | 遮挡期间位置误差、接触归属指标 | 记忆是否保留任务相关状态 |
| 接触质量 | 经标定的力、过压次数、接触丢失 | 是否以更合适方式完成 |
| 运行链路 | 延迟、实际重规划频率、恢复时间 | 新信息能否及时改变动作 |

如果只有未经力学校准的压力响应，可以报告明确命名的响应统计或饱和比例，不能直接写成牛顿。压力峰值移动也不等于物体已经到达目标区域，物体移动需要独立证据。

成功率、用力程度和完成时间可能相互制约。比较多项指标，能看出模型是否只是靠始终夹得很紧或极慢移动取得成功。

### 7.1 不确定性也需要验证

对象归属未知时，模型应有表达未知的接口。若输出概率，可以检查置信度与实际正确率是否一致，并报告不同置信阈值下的覆盖率与错误率。

但“预测某区域属于 A”“这个归属是否可判定”“A 是否能够保持”是不同事件，各自需要合适标签。一个辅助分类器的高置信度不能替代保持能力评测。

对于视觉与触觉本来无法区分的情况，应标记可观测性边界。如果独立设备提供了可靠真值，仍可保留确定的物理标签，用于概率预测和置信度校准；需要避免的是要求模型仅凭模糊输入必然输出唯一正确状态。只有连标注来源都无法核实归属时，才应标为 unknown，而不是随意指定对象或当作负例。

## 8. 泛化应拆成具体变化

“泛化更好”需要对应明确的测试轴：

| 测试变化 | 检查什么 |
| --- | --- |
| 未见对象 | 外观、形状或物理性质变化后的适应 |
| 未见对象组合 | 单个对象见过，组合与相互接触不同 |
| 身份与角色交换 | 模型是否依赖固定顺序或槽位角色 |
| 更长遮挡 | 历史信息是否随时间失效 |
| 新扰动时刻与方向 | 是否根据新反馈纠正 |
| 不同采集会话 | 零点、安装与环境变化后的稳定性 |
| 传感器缺失或延迟 | 输入有效性与时间处理是否可靠 |

这些变化应尽量分开测试，再考虑组合。直接把物体、材质、遮挡长度和传感器条件全部改变，只看到成功率下降，往往难以解释原因。

数据划分以完整 episode 为最小单位，并根据主张进一步按 session、对象或对象组合划分。连续相邻帧高度相关，不能随机分帧后把验证结果当成独立泛化。

训练损失最低的 checkpoint 不一定有最好闭环表现。模型选择应使用独立验证规则，最终测试集保留到方案固定之后。报告每种条件的试验数、随机种子与区间估计；若多个试验来自同一会话或对象组合，还应考虑相关性，避免把它们都当完全独立样本。

## 9. 一个节省复杂度的实施顺序

### 阶段 A：数据与传感器诊断

用少量接触建立、保持、释放和迁移记录，检查原始信号、mask、零点、坐标和时间。绘制数值变化与视频，确认标签对应真实事件。这个阶段的产出是可靠输入接口，不是控制结果。

### 阶段 B：小型感知诊断

比较当前帧与历史对接触事件、区域或位置的预测。若历史几乎不提供增量，先检查任务是否真的需要历史、标签是否可信、关键事件是否进入窗口，而不是立即扩大模型。

### 阶段 C：同数据上的策略对照

先训练当前观测 DP、长窗口 DP 和全局 GRU DP，保持动作与执行设置一致。确认闭环能利用触觉和历史后，再增加区域或对象结构。

### 阶段 D：遮挡、扰动与选择性操作

引入遮挡后变化、角色交换及保护对象指标。对对象级设计，同时检查归属状态和联合控制结果。若只改善辅助头、不改善操作，应继续查明策略是否读取了这些信息以及执行频率是否足够。

### 阶段 E：独立泛化与结果整理

固定训练、模型选择和测试协议，完成未见对象组合、遮挡时长与跨会话测试。报告成功条件、失败类型、实际频率及适用范围。

每一阶段都应有自己的产物：数据检查、感知结果、仿真控制、真机闭环和泛化评测分别记录。网络结构可以前后一致，但软件能运行、离线损失下降和机器人完成任务，代表的是不同层次的证据。
