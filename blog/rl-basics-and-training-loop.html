RL 基础：从交互回报到 PPO、SAC 与训练闭环

核心 · October 2026 · 8 min read核心 · 2026.10 · 约 8 分钟阅读

理解状态、观测、回报、价值与策略更新，再把奖励、探索、课程、reset 和独立评测放进灵巧手实验。

阅读位置：灵巧手 RL 研究地图 → 本文 → Teacher–Student 与部署。本章建立读论文和设计实验需要的基础，不展开完整算法推导。

1. 从“预测专家动作”到“根据后果改进动作”

Behavior Cloning 使用专家提供的观测—动作配对。RL 则让策略与环境交互，根据动作造成的后果获得奖励，再更新策略。

观测 o_t → actor → 动作 a_t → 环境
   ↑                          ↓
   └──── 下一观测 o_(t+1)、奖励 r_t、终止信息

收集的交互经验 → 估计回报 / 价值 → 更新 actor

使用示范初始化、参考轨迹或已有控制器，不会自动改变后续 RL 更新的性质。反过来，student 仅通过专家动作监督训练，即使 teacher 来自 RL，这个 student 阶段仍属于模仿学习。

2. MDP、POMDP 与机器人观测

完全可观测的 Markov 决策过程通常写为：

\[ \mathcal M=(\mathcal S,\mathcal A,P,r,\rho_0,\gamma). \]

符号 含义 灵巧手例子
\(s_t\) 环境状态 手部位置速度、物体状态、影响转移的物理量
\(a_t\) 动作 关节位置目标、速度、力矩或控制器参数
\(P(s_{t+1}\mid s_t,a_t)\) 状态转移 执行器与接触动力学
\(r(s_t,a_t,s_{t+1})\) 奖励 目标进展、稳定保持、掉落代价
\(\rho_0\) 初始状态分布 物体位置、初始抓持和任务阶段
\(\gamma\) 折扣因子 对未来奖励的相对权重

真实机器人只能获得观测 \(o_t\)。例如相机看不到掌内物体，关节编码器不能直接测出摩擦系数。这时更适合用部分可观测决策过程理解策略：

\[ a_t\sim\pi_\theta(a_t\mid h_t,g),\qquad h_t=f(o_{0:t},a_{0:t-1}), \]

其中 \(h_t\) 是历史或记忆，\(g\) 是任务目标。历史可以帮助推断隐藏状态，但不保证所有隐藏物理量都可辨识。记忆结构见 策略记忆与对象级触觉状态。

3. Reward、return、value 和 advantage

这些量的职责不同：

名称 在回答什么
Reward \(r_t\) 这一步产生了什么即时信号？
Return \(G_t\) 从现在起累计获得多少折扣奖励？
State value \(V^\pi(s)\) 在状态 \(s\) 按策略继续执行，预期回报是多少？
Action value \(Q^\pi(s,a)\) 先执行动作 \(a\)，之后按策略执行，预期回报是多少？
Advantage \(A^\pi(s,a)\) 这个动作相对策略在该状态下的平均水平好多少？

在完全可观测记号下：

\[ G_t=\sum_{k=0}^{T-t-1}\gamma^k r_{t+k},\qquad J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[G_0], \]

\[ V^\pi(s)=\mathbb E[G_t\mid s_t=s],\qquad A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s). \]

例如，某一步松开一根手指可能暂时降低接触数，却能腾出手指完成换指。只最大化当步接触数，可能永远学不到这个行为；return 用于评价动作的后续后果。奖励定义若偏离任务，长期优化仍可能得到错误行为。

4. Actor 与 critic 的分工

Actor 输出动作或动作分布；critic 估计价值，用于训练。一个常见的 value 学习目标包含：

\[ y_t=r_t+\gamma(1-d_t)V_{\bar\psi}(s_{t+1}), \qquad \mathcal L_V=(V_\psi(s_t)-y_t)^2. \]

这里仅示意 bootstrap 的含义，具体算法的目标不同；\(d_t\) 指真正的终止。若只是采样长度到上限，且任务在定义上仍会继续，就不应无条件把未来价值设为零。

Critic 的误差和 advantage 帮助优化 actor，但 critic 通常不直接给出“正确动作标签”。因此 actor–critic 不等于动作模仿意义下的 teacher–student。非对称观测的进一步区分见 RL03。

5. PPO、SAC 与 model-based 方法

5.1 PPO：用当前策略附近的数据更新策略

PPO 收集当前策略的 rollout，再对这批数据做多轮小批量更新。常见的 clipped objective 用新旧策略概率比和 advantage 构造更新目标，限制某些过大的有利方向更新；它不等于对所有状态提供严格的策略距离保证。

对灵巧手而言，PPO 可以优化目标奖励，也可以优化 tracking 奖励，还可以用于训练 teacher 或直接训练部署 actor。它并不规定这些外层接口。PPO 原论文

5.2 SAC：复用经验并加入熵目标

SAC 是 off-policy actor–critic 方法，可从 replay buffer 采样历史经验进行更新。它在任务回报之外加入策略熵目标，用来平衡收益与探索。

经验复用对昂贵交互有吸引力，但是否适合某个灵巧手任务，仍取决于数据覆盖、价值估计、奖励和实现。SAC 也可以训练 teacher；不能仅凭“off-policy”推断它一定优于 PPO。SAC 原论文

5.3 Model-based：显式利用动力学预测

这类方法学习或使用环境转移模型，生成预测、规划动作或辅助策略优化。MPC 每次规划未来一段动作，只执行前缀，再根据新状态重新规划。

PDDM 展示了学习动力学结合在线 MPC 的灵巧操作路线。接触切换会增加建模难度；采用模型需要评价预测误差如何影响实际控制。

5.4 几组互相独立的分类

维度 取值与含义
On-policy / off-policy 更新是否依赖当前策略附近的数据；是否能有效利用其他行为策略的数据
Online / offline RL 训练阶段是否继续与环境交互获取新数据
Model-free / model-based 算法是否显式使用环境转移模型进行学习或决策
Simulation / real world 交互发生在哪里
Teacher / student 模型在知识迁移流程中承担什么角色

On-policy 不表示只在一批数据上更新一次；off-policy 也不表示只使用固定离线数据。直接把普通 SAC 放到固定数据集上训练，不能自动获得可靠的 offline RL，因为未覆盖动作的价值估计仍可能出错。

6. Reward 从哪里来

6.1 目标奖励

可以根据物体目标姿态误差、抬升高度、开合角度或任务完成情况构造奖励。Dense reward 提供中间进展，sparse reward 更多依赖最终结果。

手工设计的 dense reward 可能被策略利用。例如只奖励高度，可能鼓励抛起物体；只奖励接触数，可能鼓励夹死物体。成功判定需要独立检查目标、保持时间和失败条件。

6.2 Tracking 奖励

给定参考 \(\hat{s}_{\phi_t}\)，一个示意项可以写为：

\[ r_{\mathrm{track},t}=\exp(-\alpha\,d(s_t,\hat{s}_{\phi_t})). \]

\(d\) 可比较物体位姿、指尖位置等；旋转应使用适合旋转空间的距离，不能直接把所有量混成未归一化的欧氏距离。参考进度 \(\phi_t\) 如何推进，也是方法的一部分。

Tracking 提供稠密任务信号，但若参考在机器人上不可实现，增加训练量不一定解决问题。Human2Sim2Robot 的物体中心目标与 DexTrack 的通用跟踪训练提供了不同处理思路。

6.3 模仿损失不是即时奖励

一个组合训练目标可以示意为：

\[ \mathcal L(\theta)=-J_{\mathrm{RL}}(\theta) +\lambda\mathcal L_{\mathrm{imitation}}(\theta). \]

RL 项来自交互回报，模仿项来自专家标签。也可以把示范相似度设计为 reward，但这与直接增加动作监督不是同一种梯度路径。阅读时需要确认实际实现。

7. 探索、curriculum 与 reset 都会改变学到的技能

机制 改变什么 灵巧手例子
动作探索 采样哪些动作 在策略分布或受约束技能空间中探索
初始状态分布 从哪里开始尝试 从已握住物体、桌面物体或示范中间阶段开始
课程学习 何时提高难度 增加目标角度、物体差异、扰动或任务长度
辅助控制 训练早期谁承担部分物理任务 逐渐撤掉物体支撑或虚拟驱动力
失败／困难样本采样 训练资源投向哪里 更多采样尚未掌握的换指阶段

从“已握住物体”开始学旋转，不等于学会从桌面抓起再旋转。使用示范中间状态训练，也需要在完整 episode 中检验阶段衔接。

DexMachina 用逐渐减弱的虚拟物体控制构建课程；DexMimic 的 2026 年预印本研究 value 引导的 reset 分配。这些创新改变探索条件，不要求发明新的 PPO 更新公式。

8. 一次训练实验应怎样组织

下面以“将已抓住物体转到目标姿态并保持”为示例，不包含从桌面获取物体的能力。

  1. 定义独立成功条件。 物体姿态进入容差并保持指定时间，且没有掉落；训练 reward 与这个指标分开记录。
  2. 固定观测和动作合同。 Actor 是否读取真值？动作是绝对位置还是增量？目标更新频率与低层控制频率分别是多少？
  3. 检查物理与 reset。 初始抓持是否稳定、接触几何是否合理、关节限制是否正确？
  4. 建立小规模 baseline。 先验证奖励、终止和基本可学性，再扩大随机化和物体集合。
  5. 记录资源和失败。 同时报告环境交互量、并行环境数、硬件与墙钟时间，不只报告训练小时数。
  6. 在冻结策略下评测。 区分训练物体、未见物体、不同物理参数和外部扰动，报告重复试验与波动。
  7. 验证部署观测。 若训练成功依赖特权信息，再进入 student 或感知适配阶段。

动作语义和时序的基础见 机器人数据与 Action。位置目标也会通过底层控制器产生力，不能把“输出位置”理解成“与力和接触无关”。

9. 读训练结果时常见的混淆

看到的结果 能证明什么，还不能证明什么
Reward 上升 指定奖励被优化；需要独立任务成功指标
大量并行仿真很快收敛 墙钟时间较短；环境交互总量可能仍很大
Teacher 成功率高 特权观测下有能力；不保证 student 可恢复同样信息
Tracking error 较小 接近参考；还需检查功能完成、物体保持和接触可行性
随机化后零样本部署 在所测试真机条件下可迁移；不自动覆盖所有手型和对象
Student 动作 MSE 很低 在该数据分布上接近 teacher；还需检查自主 rollout 分布
